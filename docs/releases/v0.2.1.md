# cloudivision v0.2.1

cloudivision v0.2.1 is the installable alpha release of the Kubernetes-native
CI/CD control plane. It supersedes the failed v0.2.0 publication attempt and adds
clean-runner release fixes without changing the CRD schemas.

> This release is suitable for evaluation and controlled non-production use.
> Authentication is disabled by default for local development. Review the
> [v0.2 final gate](https://alekpopovic.github.io/cloudivision/readiness/v0.2-final-gate.html)
> and enable OIDC, external secrets, network policy, backups, and provider-specific
> validation before production evaluation.

## What changed from v0.2.0

- SDK generation, scale validation, and local packaging now create the configured
  Go temporary directory, allowing release gates to run in a clean checkout.
- `cloudivision release rollback` calls the v0.2 API with an explicit source
  release, previously deployed target, actor, and reason.
- GitHub Releases use reviewed version-specific notes and include a source SPDX
  SBOM alongside checksummed platform artifacts.
- The v0.2.0 tag is retained for auditability. Its workflow stopped before image,
  artifact, or GitHub Release publication; users should install v0.2.1.

## Platform highlights

- Isolated Kubernetes Job execution, optional Tekton, rootless BuildKit and
  registry abstractions, dependency caches, bounded artifacts/logs, retry,
  cancellation, quotas, and concurrency controls.
- Signed GitHub, GitLab, Gitea, and generic webhooks with filtering, replay
  protection, and idempotent BuildRun creation.
- GitOps commits or pull requests, environment promotion, production approval,
  policy-aware rollback, and optional Argo CD or Flux health.
- Angular operations UI, CLI, generated Go and TypeScript clients, provider
  health, notifications, audit exports, and compliance reports.
- Non-root read-only workload defaults, least-privilege runner RBAC, secret
  redaction, supply-chain hooks, and rendered-chart security gates.

## Install the CLI

Linux and macOS:

```sh
curl -fsSL https://raw.githubusercontent.com/alekpopovic/cloudivision/v0.2.1/scripts/install-cli.sh | \
  CLOUDIVISION_CLI_VERSION=0.2.1 bash
cloudivision version
```

For a user-owned destination:

```sh
curl -fsSLO https://raw.githubusercontent.com/alekpopovic/cloudivision/v0.2.1/scripts/install-cli.sh
CLOUDIVISION_CLI_VERSION=0.2.1 \
CLOUDIVISION_CLI_INSTALL_DIR="$HOME/.local/bin" \
  bash install-cli.sh
```

Archives cover Linux, macOS, and Windows on amd64 and arm64. See the
[CLI installation guide](https://alekpopovic.github.io/cloudivision/operations/install-cli.html)
for manual checksum verification, Windows, and shell completions.

## Install the platform

Download the chart, CRD bundle, and `SHA256SUMS` from this release, then run:

```sh
sha256sum --check --ignore-missing SHA256SUMS
kubectl apply -f cloudivision-crds_0.2.1.yaml
helm upgrade --install cloudivision cloudivision-0.2.1.tgz \
  --namespace cloudivision --create-namespace \
  --set controller.image.tag=0.2.1 \
  --set api.image.tag=0.2.1 \
  --set runner.image.tag=0.2.1 \
  --set web.image.tag=0.2.1
```

Images are published below `ghcr.io/alekpopovic/cloudivision/` as `controller`,
`api`, `runner`, and `web`, with `0.2.1` and full-commit tags. Use immutable
digests in reviewed production values.

## Compatibility and upgrade

The stored Kubernetes API remains experimental
`cicd.cloudivision.io/v1alpha1`. v0.2.1 does not change the v0.2.0 CRD schemas.
Helm does not upgrade CRDs from a chart's `crds/` directory, so back up custom
resources, apply the attached CRD bundle, and upgrade controller, API, runner, and
web together.

## Known issues

- The Job executor runs commands inside the runner image and does not honor
  per-step images; use Tekton when distinct step images are required.
- Rootless BuildKit against a private authenticated registry and an external
  writable GitOps repository were not exercised in the local final gate.
- Optional admission webhooks, remote runners, cluster targets, and v1beta1
  conversion foundations are experimental and disabled by default.
- Six development-only Angular toolchain advisories remain; the production npm
  dependency gate reports no high or critical findings.
- The default runner image does not bundle `buildctl`; image-producing pipelines
  must provide the documented rootless BuildKit path.
