# cloudivision v0.2.0

cloudivision v0.2.0 is an alpha release of the Kubernetes-native CI/CD control
plane. It connects verified source events to isolated Kubernetes build Jobs,
immutable artifact evidence, and auditable GitOps Releases without giving the CI
runner permission to deploy application manifests.

> This release is suitable for evaluation and controlled non-production use.
> Authentication is disabled by default for local development. Review the
> [v0.2 final gate](https://alekpopovic.github.io/cloudivision/readiness/v0.2-final-gate.html)
> and enable OIDC, external secrets, network policy, backups, and provider-specific
> validation before production evaluation.

## Highlights

- Rootless BuildKit and registry abstractions, immutable digest-first image
  metadata, dependency caches, bounded artifacts and logs, retry, cancellation,
  quotas, and concurrency controls.
- GitHub, GitLab, Gitea, and generic signed webhooks with filtering, replay
  protection, and idempotent BuildRun creation.
- GitOps delivery through direct commits or pull requests, environment promotion,
  production approval, policy-aware rollback, and optional Argo CD or Flux health.
- Angular operations UI, developer/operator CLI, generated Go and TypeScript API
  clients, audit exports, compliance reports, provider health, and notifications.
- Non-root and read-only workload defaults, least-privilege runner RBAC, secret
  redaction, admission foundations, supply-chain hooks, and rendered-chart
  security gates.
- Helm packaging, CRD bundle, kind quickstart, eight runnable pipeline examples,
  conformance/upgrade/scale harnesses, and a searchable documentation site.

## Install the CLI

Linux and macOS users can install the matching release artifact with the
checksum-verifying installer:

```sh
curl -fsSL https://raw.githubusercontent.com/alekpopovic/cloudivision/v0.2.0/scripts/install-cli.sh | \
  CLOUDIVISION_CLI_VERSION=0.2.0 bash
cloudivision version
```

For a user-owned destination, download the script first and set both variables in
the same process:

```sh
curl -fsSLO https://raw.githubusercontent.com/alekpopovic/cloudivision/v0.2.0/scripts/install-cli.sh
CLOUDIVISION_CLI_VERSION=0.2.0 \
CLOUDIVISION_CLI_INSTALL_DIR="$HOME/.local/bin" \
  bash install-cli.sh
```

Release archives cover Linux, macOS, and Windows on amd64 and arm64. See the
[CLI installation guide](https://alekpopovic.github.io/cloudivision/operations/install-cli.html)
for manual checksum verification, Windows, and shell completions.

## Install the platform

Download the chart and CRD bundle from this release, verify `SHA256SUMS`, then
install into a dedicated namespace:

```sh
sha256sum --check --ignore-missing SHA256SUMS
kubectl apply -f cloudivision-crds_0.2.0.yaml
helm upgrade --install cloudivision cloudivision-0.2.0.tgz \
  --namespace cloudivision --create-namespace \
  --set global.imageRegistry=ghcr.io/alekpopovic/cloudivision \
  --set controller.image.tag=0.2.0 \
  --set api.image.tag=0.2.0 \
  --set runner.image.tag=0.2.0 \
  --set web.image.tag=0.2.0
```

The published component images are:

- `ghcr.io/alekpopovic/cloudivision/controller:0.2.0`
- `ghcr.io/alekpopovic/cloudivision/api:0.2.0`
- `ghcr.io/alekpopovic/cloudivision/runner:0.2.0`
- `ghcr.io/alekpopovic/cloudivision/web:0.2.0`

Use immutable digests in production values. Follow the
[Helm installation](https://alekpopovic.github.io/cloudivision/operations/install-helm.html),
[security hardening](https://alekpopovic.github.io/cloudivision/operations/security-hardening.html),
and [upgrade](https://alekpopovic.github.io/cloudivision/operations/upgrade.html)
runbooks rather than relying on development defaults.

## Compatibility and upgrade

The stored Kubernetes API remains experimental
`cicd.cloudivision.io/v1alpha1`. v0.2 adds fields without changing the served or
storage version, but scalar list fields for build platforms, dependency-cache
paths/restore keys, and raw-YAML files now have atomic server-side-apply semantics.

Helm does not upgrade CRDs from a chart's `crds/` directory. Back up all custom
resources, apply the attached v0.2 CRD bundle, and upgrade controller, API, runner,
and web together. A same-code live lifecycle upgrade passed; a published
v0.1.0-to-v0.2.0 rehearsal remains recommended.

## Known issues

- The Job executor runs step commands inside the runner image and does not honor
  per-step images; use the Tekton adapter when distinct step images are required.
- Rootless BuildKit against a private authenticated registry and an external
  writable GitOps repository were not exercised in the local final gate.
- Optional admission webhooks, remote runners, cluster targets, and v1beta1
  conversion foundations are experimental and disabled by default.
- Six development-only Angular toolchain advisories remain; the production npm
  dependency audit passed with no high or critical findings.
- The default runner image does not bundle `buildctl`; image-producing pipelines
  must provide the documented rootless BuildKit path.
