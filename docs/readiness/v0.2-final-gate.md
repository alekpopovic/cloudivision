# v0.2.0 final release gate

Gate date: 2026-08-23

## Summary

The v0.2.0 candidate is ready to ship as an alpha release with known issues. The
static gates pass, the chart installs on a clean Kubernetes 1.36 kind cluster,
all control-plane deployments become Available, API-backed conformance passes,
the documented dogfood BuildRun succeeds, the live lifecycle upgrade preserves
custom resources, and the limited scale run reaches 10/10 terminal BuildRuns.

The gate initially found a release-critical CRD incompatibility: Kubernetes 1.36
rejected four scalar-list schemas emitted as `uniqueItems: true`. The list fields
now use atomic server-side-apply semantics, generated and chart CRDs were updated,
and a security regression check rejects future quadratic schemas. Clean install
and all affected live gates passed after the fix.

This recommendation does not make the default chart production-ready. OIDC,
rootless BuildKit plus a real registry, an external writable GitOps repository,
and the selected optional providers still require environment-specific validation.

**Recommendation: ship v0.2.0 with known issues.**

## Critical blockers

None remain for publishing v0.2.0 as an alpha release.

The following critical findings were resolved during the gate and retested:

- Replaced forbidden quadratic `uniqueItems` validation on build platforms,
  dependency-cache paths/restore keys, and raw-YAML file lists with atomic list
  semantics. Added `no-quadratic-crd-schema.sh` to `make security-check`.
- Excluded the Angular example's local dependencies and generated output from
  product Docker contexts. The observed build context fell from 454.67 MB before
  the fix to about 42.5 kB for subsequent Go image builds.
- Made conformance stop immediately when a BuildRun unexpectedly reaches Failed
  or Cancelled, and made its success scenario inspect the checked-in Go example
  without assuming language tooling exists in the Job runner image.
- Aligned release and chart metadata from `0.1.0` to `0.2.0`.

## High-priority blockers

There are no high-priority blockers to the alpha publication. Before describing
v0.2 as production-ready, the release owner must complete these environment gates:

- Run a real rootless BuildKit build and push through the selected authenticated
  registry, verify the remote digest, and exercise denial and retry behavior.
- Run Release reconciliation against a writable GitOps repository and the chosen
  Argo CD or Flux installation, including degraded and rollback paths.
- Rehearse an actual published v0.1.0 chart/CR set to the v0.2.0 candidate; the
  local lifecycle test used the candidate chart on both sides.
- Enable and test OIDC, production audit storage, backup/restore, external secrets,
  network policy and organization mappings in the target environment.
- Resolve or explicitly accept the Job executor limitation that `step.image` is
  recorded but not honored. Job steps run in the runner image; Tekton is the
  current path for true per-step images.

## Non-blocking known issues

- Six Angular build-tool advisories remain development-only. Production npm
  dependencies audit clean.
- The Angular initial bundle exceeds its warning budget by 1.63 kB.
- The scale gate covers ten BuildRuns only and collected neither metrics-server
  resource samples nor API/log endpoint latency.
- External GitOps commit/PR behavior was not exercised in this local gate.
- The default runner image does not bundle `buildctl`; operators enabling image
  builds must provide the documented rootless BuildKit execution path.
- Optional admission webhooks, cluster targets, remote runners and `v1beta1`
  conversions remain experimental and disabled by default. The v1 plugin system
  supports trusted in-process registration only.
- The HTTP API supports Release rollback, but the CLI rollback subcommand still
  reports the older unavailable message and is not wired to the endpoint.
- Java/Maven example source and JUnit tests are present, but Maven was unavailable
  in the local host gate. Go, Node.js, Python, Angular, Helm, Kustomize and the
  Dockerfile example were executed locally.

## Goal review

1. **Image build:** BuildKit request construction, credential projection, push
   diagnostics and digest capture pass tests. Live rootless BuildKit plus a real
   registry remains an explicit post-alpha environment gate.
2. **Webhooks:** signature verification, idempotency, filters and invalid delivery
   rejection pass unit coverage; signed/idempotent GitHub delivery passes live.
3. **GitOps:** strategies and Release state transitions pass unit coverage and
   live Release creation; external repository mutation remains unverified here.
4. **UI:** debugging, logs, first-run and repository onboarding build and pass the
   Angular test suite.
5. **Security:** rendered security and RBAC checks pass, threat models are current,
   and redaction is covered. Production auth and external providers still require
   deployment-specific validation.

## Final decision

**Ship v0.2.0 with known issues** and retain the alpha label. Protect publication
on CI, production dependency audit, chart/security checks, immutable artifacts,
SBOM/provenance/signing, and release-owner review of the unresolved external
BuildKit/registry and GitOps environment gates.
