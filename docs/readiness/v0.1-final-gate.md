# v0.1.0 final release gate

Gate date: 2026-08-22

## Summary

The v0.1.0 code and release packaging are ready to ship as an explicitly alpha
release with known issues. The final gate passed on a new disposable kind cluster
(`kindest/node:v1.36.1`): Helm installed all components, controller/API/web became
healthy, the documented quickstart BuildRun succeeded with readable logs, the
API-backed conformance suite passed, the live upgrade lifecycle preserved custom
resources, and the limited scale run reached 10/10 terminal BuildRuns.

This is not a recommendation to deploy the default development configuration as
a production service. Operators must enable OIDC, provide production secret and
audit backends, and validate the external integrations they select.

**Recommendation: ship v0.1.0 with known issues.**

## Critical blockers

None for publishing v0.1.0 as an alpha release.

The gate initially found release-critical installation and runtime defects. They
were fixed and the affected live tests were repeated:

- Replaced a quadratic CRD CEL uniqueness rule with a structural list-map key so
  Kubernetes admission accepts the PipelineTemplate CRD.
- Corrected invalid Pod security-context nesting in chart templates.
- Made the nginx image run as numeric non-root UID 101 and place its PID under
  `/tmp`; added web liveness and readiness probes.
- Made pre-artifact `BuildRun.status.image` optional so early status updates pass
  CRD validation.
- Replaced inaccessible example fixture repositories with a verified public
  repository.
- Added least-privilege cross-namespace API access through Project-scoped
  RoleBindings to an otherwise unbound ClusterRole template. The controller may
  bind only that exact template; the API receives no cluster-wide binding.
- Replaced a non-portable `kubectl rollout status deployment --all` call in the
  live upgrade harness with `kubectl wait`.
- Updated supported Angular 20 patch releases and added a production dependency
  audit gate to CI and release validation.

## High-priority blockers

There are no high-priority blockers to the alpha publication. The following are
mandatory before calling a deployment production-ready:

- Configure and test OIDC. Helm's `api.auth.mode=disabled` default is deliberately
  development-only.
- Run conformance against the selected writable GitOps provider/repository and
  validate Argo CD or Flux health behavior where used.
- Exercise the selected registry, rootless image builder, signing, scanning,
  PostgreSQL audit, backup/restore, and secret-manager integrations in the target
  environment.
- Run a real cross-version upgrade when a prior published version exists.

## Non-blocking known issues

- Full npm audit reports six development-only Angular build-tool findings (three
  high and three moderate). The supported non-breaking updates are installed;
  clearing the remainder requires a breaking Angular major upgrade. Production
  dependencies audit clean and are now gated in CI.
- The live scale gate was intentionally limited to 10 BuildRuns. No metrics-server
  CPU/memory samples, API latency sample, 100/1,000 BuildRun load, 100 MB log, or
  sustained endurance result was collected.
- The external GitOps commit assertion was skipped. In-cluster Release creation,
  controller idempotency, and provider unit tests remain covered.
- Local artifacts were not SBOM-generated or signed because Syft and Cosign were
  unavailable. The public tag workflow performs image SBOM/provenance generation
  and keyless image signing.
- Runner-generated SBOM/provenance files are not automatically persisted to an
  external artifact store.
- The Kubernetes API remains experimental `v1alpha1`; the compatibility policy
  permits documented migration work in later minor releases.

## Resolved failures observed during the gate

Failures were not suppressed. Initial live attempts exposed the CRD admission
cost, invalid Pod field, nginx write/UID, early BuildRun status, stale fixture,
cross-namespace API authorization, and kubectl compatibility issues described
above. Each produced a failing command before its fix. All affected commands were
then rerun successfully on the final disposable cluster.

One checksum verification invocation was initially run outside the artifact
directory and therefore could not resolve relative paths; rerunning from the
documented artifact directory verified all files. This was a test invocation
error, not an artifact failure.

## Final decision

**Ship v0.1.0 with known issues** and label it clearly as an alpha release. Do not
claim production readiness from the default values. Protect the release tag on
the CI, production-dependency audit, artifact, signing, and documented manual
live-conformance approval gates.
