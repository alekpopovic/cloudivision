# v0.1 product readiness audit

Audit date: 2026-08-22

## Critical blockers

1. **Clean-cluster execution is unverified.** The kind creation, image loading, Helm install, sample admission and complete BuildRun/log/UI flow were not run during this audit. The scripts pass static checks, but this is not equivalent to a fresh-machine test.
2. **The existing kind E2E entrypoint is only a skeleton.** It reports prerequisites and exits without asserting the runtime flow. Prompt 22 adds the repeatable conformance coverage needed to close this gap.
3. **Cross-namespace API access needs an explicit model.** The default API Role is confined to the Helm release namespace, while Projects may create other namespaces; API log access in those namespaces is not proven.
4. **Generated CRD freshness is not reproducibly verified in CI.** Checked-in CRDs render successfully, but `controller-gen` was unavailable during this audit and `make manifests` currently treats its absence as a skipped success.

No v0.1 release should be declared ready until the clean-cluster conformance suite passes and the cross-namespace API access decision is documented and tested.

## Status definitions

- **PASS**: verified by an executable check, focused test, or direct inspection with sufficient evidence.
- **FAIL**: implementation or documentation does not meet the check.
- **UNKNOWN**: plausible implementation exists, but the required environment or end-to-end evidence was unavailable.

The npm install reported dependency advisories (3 low, 5 moderate, 28 high and 1 critical). They require a separate dependency review because applying forced upgrades is outside this documentation-focused audit and may introduce breaking changes.

## Recommended order of fixes

1. Implement and run clean-kind conformance for success, failure, duplicate Job, webhook idempotency and Release creation.
2. Decide and test the API authorization model for Project namespaces.
3. Pin controller-gen and add a generated-output drift check.
4. Add a production Helm profile that refuses development-only disabled auth.
5. Triage npm advisories with dependency reachability and supported Angular upgrade paths.
